# MJCF provenance

Two robots, two very different origins.

| model | origin |
|---|---|
| `fr3.xml`, `assets/`, `no_end_effector.xml` | vendored from **MuJoCo Menagerie**, lightly modified |
| `inspire_hand_{right,left}.xml`, `assets_hand/` | **generated** from the URDF by `../scripts/make_hand_mjcf.py` |
| `*_scene.xml`, `inspire_hand_on_flange.xml` | written here |

Everything is compiled against **MuJoCo 3.12.0**, which is what `mujoco_vendor`
0.1.0 pins on Jazzy — so the committed models were generated by the same library
that loads them at runtime.

## The FR3

| | |
|---|---|
| Upstream | <https://github.com/google-deepmind/mujoco_menagerie> |
| Path | `franka_fr3/` |
| Commit | `71f066ad0be9cd271f7ed58c030243ef157af9f4` |
| License | Apache-2.0, with an appended BSD-3-Clause (Willow Garage) block inherited from upstream `franka_description` — see `MENAGERIE_LICENSE` |

### Why Menagerie rather than converting franka_description

Menagerie's FR3 has had its inertias, `armature`, `damping` and `frictionloss`
identified under torque control — work that would otherwise have to be redone.
Menagerie's FR3 also has **no gripper**: it terminates at
`<site name="attachment_site" pos="0 0 0.107"/>` on `fr3_link7`, which
corresponds exactly to `franka_description`'s `fr3_link8` flange frame
(`joint8` in `robots/fr3/kinematics.yaml`: xyz `0 0 0.107`, rpy `0 0 0`).

### Local modifications to `fr3.xml`

All three are marked inline with a `LOCAL MODIFICATION` comment.

**1. `<position>` actuators → `<motor>`.** `mujoco_ros2_control`'s
actuator/command-interface compatibility matrix is:

| command interface | MuJoCo `position` | MuJoCo `velocity` | MuJoCo `motor` |
|---|---|---|---|
| position | native | via PID | **via PID** |
| velocity | not supported | native | **via PID** |
| effort | **not supported** | **not supported** | **native** |

An incompatible pairing is a **hard error at controller_manager startup**, not a
warning. Since both position and effort controllers are wanted, the actuators
must be `<motor>`. Upstream's `kp`/`kv` servo gains are consequently dropped —
the equivalent tuning now lives in `../config/pids.yaml`. `ctrlrange` mirrors
each joint's own `actuatorfrcrange` (±87 Nm for joints 1–4, ±12 Nm for 5–7),
matching `franka_description`'s URDF effort limits.

**2. `home` keyframe `ctrl` zeroed, `qpos` set to Franka's home pose.**
Upstream's `ctrl` is correct only for `<position>` actuators, where it is a
setpoint. With `<motor>` actuators `ctrl` is a **torque**, so carrying those
values over would apply constant torques of up to 1.57 Nm on the first timestep.

**3. An `<attach>` slot for the end effector**, inside `fr3_link7` at the flange
frame. `end_effector` is a model asset the *scene* supplies, which is what lets
one arm file serve every scene here:

| scene binds `end_effector` to | result |
|---|---|
| `no_end_effector.xml` | bare flange; the stub also materialises the `fr3_link8` body |
| `inspire_hand_on_flange.xml` | the hand bolted to the flange |

Two constraints, both learned the hard way:

- The `<model>` asset must be declared **before** `<include file="fr3.xml"/>` —
  `<attach>` is resolved during parsing, not at compile time.
- `<attach>` has no `site` attribute in XML (that exists only in the `MjSpec`
  API), so the element has to sit textually inside the parent body.

### Known mismatch: MJCF joint ranges are tighter than the URDF's

Menagerie applies a safety margin, so the MJCF `range` is narrower than
`franka_description`'s `<limit lower/upper>` on every joint. Consequence: a
controller validating against the URDF will accept a goal near the URDF limit
that MuJoCo then silently clamps, so the joint appears to stop short. This is a
*simulation* artefact — do not "fix" it by widening the MJCF, since the margin
reflects the real robot's safe operating range.

## The Inspire hand

Generated, not vendored. `../scripts/make_hand_mjcf.py` imports
`inspire_hand_description`'s URDF through MuJoCo's own URDF importer and then
adds the four things a URDF cannot express. The import itself is good — 12
joints with the right ranges, 9 meshes, visual and collision geometry correctly
separated — so the script only supplies what is missing:

**1. The finger coupling.** MuJoCo's URDF importer drops `<mimic>` silently. Six
joints would be free-swinging and the hand would hang open. They come back as
`<equality><joint>` constraints whose `polycoef` is the same affine map. The
constants live in `make_hand_mjcf.py`'s `COUPLINGS` and are checked against the
URDF and the driver by `../test/test_mjcf.py`.

**2. Actuators.** Six `<motor>`, one per driven joint, ±1 Nm — for the same
reason the FR3 uses `<motor>`. ±1 Nm is upstream's declared `<limit effort>`,
which is a placeholder rather than a measurement, but is the right order of
magnitude: the RH56 manages roughly 10 N at a fingertip on a ~50 mm lever.

**3. Joint dynamics.** The description declares none anywhere.
`damping=0.1`, `armature=0.002`, `frictionloss=0.005` are the smallest values
found to hold a curl steady at a 2 ms timestep without visibly slowing the
finger. They are stabilisers, not identified parameters.

**4. Contact excludes.** This one is not obvious and is worth reading before
touching the model.

MuJoCo excludes contacts between a parent body and its child — **except** when
the parent belongs to the world weld. For a hand standing on a bench, every
joint from `world` down to `hand_base_link` is fixed, so the palm *is* the world
body as far as that filter is concerned, and the filter never fires. The palm's
collision geometry is a coarse envelope (a cylinder and seven boxes, because
upstream gives it no collision mesh) that intersects every finger root by
11–14 mm at the **open** pose. Left alone, the hand starts jammed: it closes
sluggishly against a constraint force of order the entire actuator budget, and
will not reopen at all.

The generator therefore re-adds every parent/child exclude explicitly — not just
the palm's, so the model behaves identically bolted to the flange (where the
filter would have applied) and on the bench (where it would not).

One further pair is excluded, `hand_base_link` ↔ `thumb_proximal`, which is a
*grandchild* and so not covered by that rule. It was found by sweeping all six
driven joints over 3000 random in-range poses: that pair sits at −12.1 mm at
every one of them, while every other overlap varies with the pose and bottoms
out only where the thumb is genuinely driven into the index finger. Those are
real self-collisions and are left alone. Re-run that sweep if the model is
re-vendored; a finer palm mesh would make the exception unnecessary.

With the excludes in place, all three scenes rest at **zero contacts**, and a
finger driven closed and then open returns to its limit and settles to zero
velocity.

## Keyframes, and why the combined scenes define a third one

`fr3.xml` defines `home` (the arm's seven joints) and the generated hand defines
`open` (its twelve). MuJoCo **zero-pads** a keyframe to the full model, so in a
scene containing both:

- `home` would put the hand's followers at 0 instead of −0.04545, starting the
  simulation in violation of its own equality constraints;
- `open` would put the arm at all-zeros — fully extended.

Neither can be redefined, because a duplicate key name is a hard error. So the
combined scenes define `start`, covering all nineteen joints, and the launch
selects it. `inspire_franka_sim/launch/sim.launch.py` maps scene → keyframe in
its `KEYFRAMES` table.

## Keeping the MJCF and the URDF honest

`ros2_control` matches the description to the simulator **by joint name**, and
checks nothing else. A joint the URDF declares and the MJCF does not is caught
at startup; a joint present in both but in the wrong place, or coupled
differently, is not caught at all. `../test/test_mjcf.py` covers that gap: joint
sets per scene, actuators only on driven joints, couplings equal to the URDF's
`<mimic>` values, zero contacts at rest, the combined rest pose, and the bench
hand's placement matching `hand_bench_xyz` in the description.

## Re-vendoring the FR3

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/google-deepmind/mujoco_menagerie
cd mujoco_menagerie && git sparse-checkout set franka_fr3
# copy fr3.xml plus only the assets/ files it references, and LICENSE -> MENAGERIE_LICENSE,
# then re-apply the three local modifications above and update the commit hash here.
```

Regenerating the hand needs no arguments:

```bash
python3 scripts/make_hand_mjcf.py --side right
python3 scripts/make_hand_mjcf.py --side left
```
